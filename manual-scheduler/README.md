# Расписание

Самостоятельный редактор на FastAPI + Vue. Редактор хранит собственную базу. По кнопке «Опубликовать» отправляет расписание в UTB2 через защищённый API. timetable-system отключён от UTB2.

## Запуск локально

Из этой папки, в первом терминале:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
backend/.venv/bin/uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8010
```

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5174. Нужен Node.js 22.12+ (или 20.19+). База создаётся автоматически в `backend/schedule.db`; можно переопределить путь переменной `SCHEDULER_DB`. Для резервной копии остановите API и скопируйте этот файл.

При первом запуске добавьте справочники либо нажмите «Загрузить пример». Демоданные добавляются только по нажатию и только в пустую базу.

## Работа

- В справочниках добавьте кабинеты, преподавателей, группы и предметы. Названия уникальны внутри каждого справочника. Для разных корпусов используйте различимые названия кабинетов, например `А / 106`.
- Нажмите «+» в свободной ячейке. В окне выберите преподавателя, предмет, тип занятия и группы, затем нажмите «Поставить пару». День, время и кабинет заполнены по выбранной ячейке; их можно изменить в окне.
- Несколько групп в занятии образуют поток. Занятие общее для всех выбранных групп.
- Правая кнопка мыши по занятию открывает меню «Изменить», «Копировать», «Удалить». Меню также доступно через Shift+F10 на карточке. Для переноса можно перетащить карточку. Изменение и копирование открывают окно выбора дня, времени и кабинета.
- Пересечения преподавателя, группы и кабинета блокируют запись. Вместимость, профиль кабинета и чужая кафедра специализированного кабинета требуют подтверждения, но не запрещают сохранение. Кафедра кабинета сравнивается с кафедрой преподавателя.
- Переключатели показывают неделю группы или преподавателя из тех же данных. Кнопка экспорта Excel убрана из интерфейса.

## Границы первой версии

Приложение использует общий аккаунт сотрудников. Публикация на студенческий сайт выполняется вручную кнопкой «Опубликовать». Недельное расписание повторяется; чётность недель и календарные даты пока не моделируются. Слоты фиксированы: 08:00–08:50 … 20:00–20:50. Автоматического составления и предварительной нагрузки нет.

Запись проверяется в транзакции SQLite: два одновременных добавления не смогут занять один кабинет/преподавателя/группу. SSE обновляет данные в браузерах после изменений (проверка ревизии каждые 0,5 секунды). Версии занятий и справочников защищают от перезаписи и удаления устаревшей записи. При потере связи браузер переподключается; формы и фильтры не сбрасываются.


Тесты используют временную отдельную базу.

## Поиск и перенос справочников

Поля преподавателя и предмета поддерживают поиск по части названия (преподаватель — также по кафедре), выбор мышью или стрелками и Enter. Списки показывают первые 60 совпадений; уточните запрос для остальных. Поиск также доступен в недельном виде.

Корпуса и кафедры доступны отдельными вкладками справочников. Переименование обновляет связанные записи; удаление используемых корпуса/кафедры блокируется.

Импорт из согласованной SQLite-копии `timetable-system`, из папки backend:

```bash
.venv/bin/python import_timetable.py /path/to/staff.sqlite --dry-run
.venv/bin/python import_timetable.py /path/to/staff.sqlite
```

Источник открывается только для чтения. Перед импортом сохраняется копия целевой базы в `backend/backups/`. Импорт переносит корпуса, кафедры, кабинеты, преподавателей, группы и предметы, сохраняя вместимость, количество студентов, курс и принадлежность к кафедре. Расписание не переносится и не удаляется. Записи одинакового вида и названия обновляются с сохранением их ID; остальные существующие записи сохраняются. Для повторного импорта сохраняется ID записи в исходном справочнике. Номера кабинетов дополняются корпусом, повторяющиеся коды групп — курсом (при необходимости исходным ID). Длинные названия предметов сохраняются полностью.


## Общий вход и совместная работа

Перед первым входом создайте общий аккаунт из папки backend:

```bash
.venv/bin/python manage_account.py admin
```

Пароль вводится скрыто (не меньше 12 символов). На этом ноутбуке аккаунт уже создан; первоначальные данные лежат в `backend/admin.credentials` (файл с правами 0600, исключён из Git). Все сотрудники используют один логин и пароль, но получают отдельные сеансы. Выход завершает только текущий сеанс; смена пароля через эту команду завершает все сеансы. Сеанс действует 12 часов.

Для совместной работы все компьютеры должны открывать один адрес сервера с одной базой. Несколько локальных копий SQLite не синхронизируются. Используйте HTTPS и `COOKIE_SECURE=true` при запуске API за HTTPS-прокси. В локальном HTTP-режиме оставьте `COOKIE_SECURE=false` (значение по умолчанию).

Прокси должен направлять `/api/` на FastAPI; для `/api/events` отключите буферизацию и увеличьте таймаут чтения. Пример настроек location в Nginx:

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8010;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 60s;
}
```

Heartbeat идёт каждые 10 секунд; соединение проверяет срок и отзыв сеанса. Ревизия хранится в SQLite и меняется триггерами в той же транзакции, что данные, поэтому SSE работает и при нескольких процессах API. Изменения CLI-импорта тоже обнаруживаются. За общим аккаунтом нельзя определить конкретного автора правок.

При обновлении существующей установки сделайте резервную копию `schedule.db`: сервер автоматически добавляет версии записей, журнал ревизии и таблицы авторизации. Пароли хранятся в виде scrypt-хеша, токены сеансов — в виде SHA-256-хеша. Не публикуйте базу, резервные копии и файл доступа.

## Публикация в UTB2

В backend/.env задайте STUDENT_PUBLISH_URL (полный адрес нового endpoint,
например http://127.0.0.1:8001/api/v1/manual-publication) и PUBLISH_SECRET_KEY —
тот же секрет минимум 32 символа, что у UTB2. Файл автоматически читается при
старте API, системные переменные имеют приоритет. Секрет не передаётся браузеру.
На этом ноутбуке настройки уже созданы для локального student API на порту 8001.

Кнопка «Опубликовать» находится в шапке. Отправляется всё расписание, независимо
от фильтра/дня, все группы (включая пустые) и преподаватели. Потоки представлены
у каждой группы и один раз у преподавателя. Время совпадает с сеткой редактора:
08:00–08:50 … 20:00–20:50. Названия предметов не обрезаются.

До следующей публикации UTB2 показывает прежнюю версию. В редакторе видны дата
публикации, наличие неопубликованных правок и результат отправки. При ошибке связи
повторите публикацию; номера версий защищают от устаревшей доставки. Новый снимок
строится в транзакции; сетевой запрос не блокирует редактирование. Параллельные
правки во время отправки остаются неопубликованными. UTB2 заменяет данные одной
транзакцией, сохраняя предыдущую публикацию при откате.

Совместный Docker-запуск и переход с действующего сервера описаны в
[deploy/README.md](deploy/README.md). Старый том staff_data не используется;
базу manual-scheduler нужно перенести в отдельный manual_data до первого запуска.

Сквозные проверки:

```bash
cd backend
.venv/bin/pip install -r requirements-integration.txt
.venv/bin/python -m unittest -v test_api test_collaboration test_import_timetable test_publication
```

## Статистика посещений

После входа откройте вкладку «Статистика» в редакторе. Отчёт получает данные
из UTB2 по тому же защищённому соединению, что публикация; дополнительных ключей
или сторонних сервисов не требуется. Статистика доступна всем, кто вошёл в общий
аккаунт редактора. На публичном сайте endpoint отчёта закрыт прокси.

Показатели: уникальные браузеры, визиты (новый после 30 минут бездействия),
просмотры расписаний, активные посетители за последние 5 минут, повторные
посетители и ошибки загрузки. Есть график по дням, популярные группы и преподаватели,
устройства и браузеры. Периоды: сегодня, 7, 30, 90 и 180 дней; время Алматы.
Страница автоматически обновляет отчёт раз в минуту, пока открыта и видима.

Уникальный браузер — приблизительная оценка числа людей. Очистка хранилища или
другое устройство создаёт нового посетителя. Автообновления расписания не считаются
новыми просмотрами. DNT/GPC и недоступное хранилище могут исключать посещения из
подсчёта; API-запросы обоев iOS отдельно не учитываются. IP и полные URL источников
переходов в таблице аналитики не сохраняются. Сбор уже встроен в UTB2: ранее
сохранённые события появятся в отчёте; отсутствующая история не восстанавливается.

Проверка: `python -m unittest -v test_analytics` из backend, с зависимостями
requirements-integration.txt. Клиентский счётчик: `node test_analytics.js` из UTB2/frontend.
